## 1. 0.10.3 历史基线结论

0.10.3 基线源码已彻底替换 Windows 全局快捷键链路：Windows 只使用系统托管的
`RegisterHotKey + MOD_NOREPEAT`，默认 `Ctrl+Shift+Space`；Raw Input、低级键盘 hook、按键轮询和
双修饰键状态机均不再存在。旧版 Windows 双修饰键和 Win32 不支持的组合键配置会迁移并保存，
Windows 设置页只显示“快捷键”标签与组合键录入框；注册冲突时可回滚最近可用配置或回退默认组合键，
默认键也冲突时停止重试。偏好设置标题下的重复功能说明已移除。
热键触发、窗口原生激活和 Windows 失焦隐藏不再由相互竞争的 Qt 定时器共同决定；可见但未获前台的
面板会重新激活。原生 Win32 剪贴板宿主现在是 Windows 剪贴板唯一读写者；GUI 不再通过 Qt/OLE
写入。文本、文件和图片分别 eager 提交 `CF_UNICODETEXT`、`CF_HDROP + Preferred DropEffect`、
`PNG + CF_DIBV5 + CF_DIB`，使用清零的可移动 HGLOBAL。写入 ACK 先确认 sequence 推进，再以
owner、request marker 与完整格式核验事务身份；粘贴前允许桌面客户端格式协商造成的合法 sequence
推进，但必须在当前稳定 sequence 上重新核验同一身份。热键事件同时快照目标顶层窗口与实际焦点
窗口的 HWND/TID/PID；发送前恢复并复核两者，`Ctrl+V` 使用单次原生 `SendInput` 且要求四个事件
全部提交，成功提示收窄为“已触发粘贴”。需要输入队列附加时只启动一次性原生 focus helper，
Qt GUI 线程不再调用 `AttachThreadInput`；helper 以 1.5 秒硬超时、checked detach 和进程退出作为
最终清理边界。异步重建输入控件的桌面客户端另有 40/80/120 ms 有界焦点复核。三格式位图按
128 MiB 原始像素总入口限制峰值。
文件历史继续使用 revision CAS 的后台有效性扫描与发送前异步复核。

心跳、启动握手、每代 nonce、父进程死亡退出、序号重放、原子 manifest、路径校验
和清空代次失效均有自动化覆盖。核心功能与 Qt 界面已在当前 macOS 主机完成全量回归；Windows 原生
API 使用可注入替身验证；热键触发时的目标 HWND 快照、`AllowSetForegroundWindow` 权限交接、
一次性 helper 输入队列附加/解除和输入法 preedit Enter 门禁均有回归。Windows 标签构建会在冻结
EXE 上真实写入并读取文本、文件和图片，在剪贴板 helper 退出后再次读取 PNG/DIB，并以有硬超时的
Win32 probe 调用冻结 EXE 的 focus helper，再由冻结 EXE 使用与主进程共享的实现跨进程执行
`SendInput`：文本分支核对 EDIT 内容，图片分支要求目标 EDIT 确实收到 `WM_PASTE`，并在消息到达时
确认 `PNG / CF_DIBV5 / CF_DIB` 均可用；focus smoke 与生产共用同一个 1.5 秒超时常量。
该基线验收主机不是 Windows，不能把替身测试和待运行的标签 CI 表述为 Windows 10/11 聊天客户端
端到端通过。后文 macOS 0.10.0 arm64 包的构建验证以及 0.9.5 的真实启动与界面数据作为历史运行
基线保留，不作为 v1.1.3 源码的新打包结论。
